## Definition
[[Embeddings]] are vector representations of text that make source chunks and user questions comparable for semantic retrieval.

## Current Synthesis
Embeddings convert raw text into vectors that retrieval systems can search. Document chunks are embedded and stored, user questions are embedded at query time, and similarity between those vectors determines which source passages become context for the language model.

Embedding choices also affect database behavior. Dimensionality changes the cost of exact search because each candidate comparison spans every vector dimension; the pgvector example uses 1,536-dimensional Titan vectors in PostgreSQL and searches prompt embeddings generated by the same model.

## Key Claims
- Embeddings convert text into model-usable vector representations.
- Both source chunks and user questions need embeddings for similarity search.
- Embeddings are central to connecting unstructured private documents with LLM context windows.
- LangChain can call embedding APIs as part of the application workflow, and embedding preparation can be an explicit preprocessing step before chat begins.
- Embedding vectors can be stored in PostgreSQL through pgvector and indexed for faster similarity search.
- The same embedding model should be used for stored documents and query prompts in a similarity-search pipeline.
- Higher-dimensional vectors make exhaustive exact search more expensive because each comparison spans many dimensions.

## Evidence
- Text-to-vector step: [[ling-ji-chu-da-jian-ji-yu-si-yu-shu-ju-de-chatgpt]] identifies vectorization as the key step after document chunking.
- Question vectorization: [[ling-ji-chu-da-jian-ji-yu-si-yu-shu-ju-de-chatgpt]] says the user's question is also vectorized for similarity retrieval.
- Private-data bridge: [[ling-ji-chu-da-jian-ji-yu-si-yu-shu-ju-de-chatgpt]] explains that retrieved chunks are then supplied to the LLM as context.
- OpenAI integration: [[ling-ji-chu-da-jian-ji-yu-si-yu-shu-ju-de-chatgpt]] says the Replit sample uses LangChain to call OpenAI's embeddings interface.
- Preprocessing flow: [[ling-ji-chu-da-jian-ji-yu-si-yu-shu-ju-de-chatgpt]] has readers run an embedding mode before conversation mode.
- Database storage: [[aws-blog-optimize-generative-ai-applications-with-pgvector-indexing]] stores Titan-generated vectors in PostgreSQL using pgvector.
- Dimensionality cost: [[aws-blog-optimize-generative-ai-applications-with-pgvector-indexing]] uses the 1,536-dimensional Titan output to explain why exact nearest-neighbor comparison can become expensive.
- Prompt consistency: [[aws-blog-optimize-generative-ai-applications-with-pgvector-indexing]] says prompts are converted with the same embedding model used for documents before vector search.

## Counterevidence & Qualifications
The sources do not evaluate embedding model choice across providers, multilingual retrieval quality, chunk overlap, drift, cost, or recall metrics. The AWS source gives one Titan embedding configuration rather than a general embedding-model benchmark.

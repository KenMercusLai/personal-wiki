## Overview
[[Amp]] is the company and coding-agent product represented in the wiki through its February 2026 strategy announcement, “The Coding Agent Is Dead.”

## Current Profile
The source presents Amp as a frontier-oriented coding product willing to discard successful interfaces when model capability changes the useful product boundary. Amp announced the end of its VS Code and Cursor extensions, retained its CLI as a transitional surface, and described its longer-term direction as moving beyond a conventional coding agent toward less supervised execution.

## Key Characteristics
- Positions model capability, rather than an elaborate agent wrapper, as the main source of current coding performance.
- Favors a lightweight CLI because it can run outside an editor and support unattended work.
- Treats product self-disruption as preferable to optimizing around a temporary interface or business-model peak.
- Targets users comfortable following a rapidly moving technical frontier.

## Evidence
- Product transition: [[the-coding-agent-is-dead]] announces that Amp's VS Code and Cursor extensions would stop working on March 5, 2026 while the CLI remained available.
- Technical stance: [[the-coding-agent-is-dead]] argues that strong coding models can often work through `bash` and that agent wrappers are becoming less differentiating.
- Strategic posture: [[the-coding-agent-is-dead]] explicitly frames the CLI as a temporary ladder and allows that Amp's next form may also be discarded.

## Qualifications
The current profile comes from one first-party strategy post. It does not identify every relevant model, compare Amp with alternative agents, report migration outcomes, or establish that editor integration, harness design, pricing, and supervision no longer matter across tasks and risk levels.

## Overview
[[MaterialDesign]] appears in this source as the visual design system used by [[Firebase]], which required the [[Crashlytics]] team to redesign the product's interface when migrating from [[Fabric]].

## Current Profile
The source treats Material Design as a constraint and opportunity. Because Firebase used Material Design and had a very different visual system from Fabric, Crashlytics needed at least a visual update. The designer used that requirement to make a broader case for changing user flows and information hierarchy rather than performing a surface-level port.

## Key Characteristics
- Functions as Firebase's visual design system in the source.
- Created a mismatch with the existing Fabric Crashlytics interface.
- Forced a visual update during the Crashlytics migration.
- Became part of the redesigned Firebase Crashlytics surface visible in inspected screenshots.
- Served as the catalyst for a deeper [[ProductRedesign]] argument.

## Evidence
- Design-system role: [[advocating-for-a-complete-product-redesign-google-design-medium]] says Firebase uses Material Design and has a very different visual design system.
- Visual-update trigger: [[advocating-for-a-complete-product-redesign-google-design-medium]] says the need for a visual design update created the opportunity to rethink the entire user experience.
- Screenshot evidence: [[advocating-for-a-complete-product-redesign-google-design-medium]] shows the redesigned Firebase Crashlytics UI with lighter Material-style surfaces, cards, filters, tables, and action controls.

## Qualifications
The source does not explain Material Design's full guidelines, component system, or evolution. It only shows how adopting the system affected one product migration.

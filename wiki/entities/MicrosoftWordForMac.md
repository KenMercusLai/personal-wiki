## Overview
[[MicrosoftWordForMac]] is the source's product case for customer-centered platform specificity after an internal code-convergence strategy harmed the Mac experience.

## Current Profile
The source presents Word for Mac 6.0 as a cautionary product-management case. Microsoft wanted one Word code base across Windows, DOS, and Mac to save development time and ship a feature-rich release, but Mac customers experienced the product as slow and insufficiently native. The 6.1 recovery focused on Mac performance, fonts, shortcuts, and user-visible workflows, turning the lesson into a broader product claim: internal efficiency is an empty victory if the resulting product is not good for its actual users.

## Key Characteristics
- Mac version of Microsoft Word affected by the Word 6.0 common-code-base strategy.
- Suffered serious user backlash because the release was too slow on typical Macs.
- Became a case for prioritizing platform-specific customer experience over uniform feature parity.
- Improved through performance work and Mac-specific affordances in Word 6.1.
- Helped motivate later separation of Microsoft Mac work from Windows-centric teams according to the source.

## Evidence
- Convergence pressure: [[behind-every-great-product-silicon-valley-product-group]] says Microsoft wanted a single code base across Windows, DOS, and Mac.
- Customer backlash: [[behind-every-great-product-silicon-valley-product-group]] says Mac users complained that the release crawled and interpreted it as Microsoft trying to harm the Mac.
- Platform-specific focus: [[behind-every-great-product-silicon-valley-product-group]] says the team learned users value what is different about their platform.
- Recovery work: [[behind-every-great-product-silicon-valley-product-group]] describes performance, font-loading, keyboard-shortcut, and Word Count improvements.
- Strategic reversal: [[behind-every-great-product-silicon-valley-product-group]] says Microsoft later diverged the code base and separated the teams.

## Qualifications
The source gives a product-management narrative rather than a full technical postmortem. It does not include performance measurements, internal Microsoft planning documents, or Mac customer survey data.

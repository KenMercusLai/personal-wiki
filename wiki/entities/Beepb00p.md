## Overview
[[Beepb00p]] is the author of the mapped personal data infrastructure source and the maintainer behind the article's linked personal-data tools and scripts.

## Current Profile
The source presents beepb00p as a practitioner building personal infrastructure around [[DataLiberation]], local files, small export scripts, and reusable personal-data interfaces. The diagram positions the author's work as both a private operating system for personal records and public documentation for others interested in data ownership.

## Key Characteristics
- Builds personal infrastructure to approximate a [[PersonalDataMirror]].
- Uses public writing, diagrams, and GitHub-linked tools to explain the stack.
- Treats poor interoperability as a practical engineering problem rather than only a policy complaint.
- Connects many small data exporters into filesystem artifacts and [[HumanProgrammingInterface]] modules.
- Values continuity across platform shutdowns, as shown by the Endomondo-to-RunnerUp compatibility example.

## Evidence
- Infrastructure map: [[blog-beepb00p-map-of-my-personal-data-infrastructure]] describes the article as a map of the author's personal data liberation infrastructure.
- Tool ecosystem: [[blog-beepb00p-map-of-my-personal-data-infrastructure]] links diagram nodes for exporters, [[HumanProgrammingInterface]], [[Promnesia]], and [[Orger]].
- Interoperability stance: [[blog-beepb00p-map-of-my-personal-data-infrastructure]] says the project exists partly to show the complexity caused by poor interoperability.
- Platform continuity: [[blog-beepb00p-map-of-my-personal-data-infrastructure]] says discontinued services such as Endomondo can remain useful when exported data stays compatible.

## Qualifications

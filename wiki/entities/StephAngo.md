## Overview
[[StephAngo]] is the author of “How I use Obsidian,” a practitioner account of a file-based, link-heavy personal vault and publishing workflow.

## Current Profile
In the available source, Ango presents a personal system designed to reduce filing and decision overhead. He keeps most authored notes at the vault root, distinguishes external references and other people's clippings, uses categories and properties for overlapping views, links first mentions liberally, and periodically revisits material by hand. The same preference for controllable Markdown files extends into a Jekyll-based website workflow, though the site is kept in a separate vault as a pragmatic exception.

## Key Characteristics
- Treats user-controlled, readable files as the durable substrate beneath a note application.
- Prefers a few explicit conventions over repeated organizational decisions.
- Uses links, categories, properties, templates, and search more than nested folders.
- Aggregates timestamped fragments through periodic reviews and revisits older notes randomly.
- Keeps understanding-oriented maintenance manual even when language-model automation is possible.
- Writes and publishes from Markdown through an Obsidian-centered static-site workflow.

## Evidence
- File custody and structure: [[how-i-use-obsidian]] defines a vault as an ordinary folder and describes a root-heavy layout with limited reference and administrative folders.
- Linking and retrieval: [[how-i-use-obsidian]] uses first-mention links, unresolved links, backlinks, quick switching, categories, local graphs, and random-note traversal.
- Review practice: [[how-i-use-obsidian]] compiles daily fragments into larger reviews and argues that manual maintenance reveals personal patterns.
- Reusable conventions: [[how-i-use-obsidian]] documents plural naming, ISO dates, a seven-point rating scale, shared properties, and composable templates.
- Publishing: [[how-i-use-obsidian]] describes pushing Markdown through GitHub, Jekyll, and Netlify while retaining a separate site vault.

## Qualifications
This profile is based on one self-authored workflow page rather than independent biography or comparative evaluation. The source describes what Ango prefers and practices; it does not establish that the same vault shape, review cadence, plugins, rating scale, or publishing stack will suit other people.

## Summary
[[NicholasCarlini]] argues that current large language models are already useful in ordinary technical work, even without assuming they will automate all jobs or keep improving at the same pace. The essay documents concrete [[PracticalLLMUse]] across application building, learning new tools, blank-page code starts, simplification, repetitive tasks, API lookup, hard-to-keyword search, one-off scripts, teaching, and error fixing. Its main contribution to the wiki is a practitioner taxonomy: LLMs raise the floor for non-experts and speed experts when the task is bounded, inspectable, and easy enough for the user to judge.

## Key Claims
- Current LLMs can materially improve programmer productivity even when their hallucinations, robustness limits, and ethical issues remain real.
- [[PracticalLLMUse]] is strongest for bounded work: scaffolding apps, generating boilerplate, writing one-off scripts, formatting data, explaining APIs, and interpreting errors.
- LLMs help users enter unfamiliar technical domains by giving interactive, goal-specific tutoring rather than static documentation alone.
- AI assistance raises the "power user" floor by making complex transformations and automation accessible through natural-language requests.
- LLM outputs are useful starts, references, or tutors, not guarantees of correctness; the author keeps the emphasis on concrete workflows rather than speculative automation claims.

## Key Quotes
> "they're useful now" - on the essay's intentionally narrow claim.

> "Is it perfect? No way! But it's a start." - on using LLMs to overcome blank-page friction.

> "I just want the answer spoon-fed to me." - on using LLMs as an API/reference shortcut.

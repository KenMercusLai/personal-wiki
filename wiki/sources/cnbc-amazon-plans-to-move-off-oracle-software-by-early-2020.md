## Summary
[[CNBC]] reports that [[Amazon]] planned to complete a years-long migration away from [[Oracle]] proprietary database software by the first quarter of 2020, after already moving much of its infrastructure to [[AWS]]. The article frames the move as both an internal scalability response and a public competitive signal: Amazon's own retail operations were reducing dependence on a supplier that had become a cloud and database rival. No effective image references were present in the source markdown.

## Key Claims
- Amazon had already moved much of its infrastructure to AWS and planned to be completely off Oracle proprietary database software by the first quarter of 2020.
- The migration reportedly began around 2013 or 2014, with some core shopping systems still using Oracle in 2018 and a remaining estimated completion window of 14 to 20 months.
- Amazon's primary Oracle problem was described as database scalability relative to Amazon's performance needs, and new Oracle-dependent development had reportedly slowed or stopped.
- The database migration sat inside a broader [[EnterpriseCloudMigration]] story: AWS was growing rapidly while Oracle struggled to match the shift from traditional data centers to cloud workloads.
- Oracle disputed the competitive implication by pointing to Amazon's continued Oracle spending and claiming AWS lacked database technology comparable to Oracle Database.
- The Amazon-Oracle rivalry included public remarks from [[LarryEllison]] and [[AndyJassy]], as well as AWS services such as [[AmazonAurora]] and Database Migration Service aimed at Oracle's core market.

## Key Quotes
> "a long way away in the cloud" - Jassy's CNBC criticism of Oracle's cloud position.

> "They can't do it." - Ellison's claim that Oracle database customers could not run mission-critical workloads at Amazon.

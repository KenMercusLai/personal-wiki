## Summary
[[DanielWessel]] describes a large personal reference archive in [[DEVONthink]], reporting that a roughly 29 GB database with about 50,000 files remained usable for his work. His organization model combines one shared database, stable top-level groups, content-based duplicate detection, synchronized replicants, smart groups, and selective tags so material can keep a primary location while appearing in several project or topic views. The article also gives source-scoped interface, backup, image-import, and sorting tips.

## Key Claims
- A large [[DigitalArchiveOrganization|digital archive]] can use one authoritative database when cross-domain reuse matters and access boundaries do not require separate stores.
- Stable groups provide primary context, while smart groups and selective tags create overlapping views without physically duplicating every item.
- DEVONthink replicants let one document appear in active-work and reference contexts while remaining synchronized.
- Content-based duplicate detection is more reliable than filename comparison when identical files arrive under different names.
- Allowing same-named files in one group makes import cleanup easier because collision handling does not interrupt comparison.
- Image workflows should preserve originals by exporting masters or best-quality versions before import; direct transfer from Aperture could downscale them in the author's setup.
- Large visual collections can be triaged through icon views and binary category/not-category windows, while non-exclusive classifications are better expressed through tags and smart groups.

## Key Quotes
> "the best collection I have used so far" - Wessel's 2011 assessment after continuing to use DEVONthink Pro Office.

> "all active material into one database" - on keeping work and private reference material available for cross-topic reuse.

> "Don't tag entire collections" - on reserving tags for discriminating items rather than applying broad labels indiscriminately.

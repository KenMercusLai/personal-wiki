## Summary
[[AndrejKarpathy]] reflects that [[Micrograd]] attracted modest GitHub interest until he published a video building it from scratch, after which the same code saw much larger engagement and became a common reference for learning backpropagation. The post argues that technical artifacts, even when short, commented, and well documented, can still need an accessible ramp for both beginners and experts. The inspected SVG is a simple rising-chart icon that visually reinforces the growth claim but adds no separate technical evidence.

## Key Claims
- [[TechnicalAccessibility]] can multiply the reach of the same underlying work by lowering the effort needed to engage with it.
- Technical creators often overestimate how self-explanatory code, papers, comments, and README files are to other people.
- Expert audiences can also avoid otherwise understandable work when the initial barrier to entry feels too high.
- [[Micrograd]] became much more influential as a learning artifact after Karpathy paired the minimal codebase with a from-scratch explanatory video.
- The practical sequence is to build the artifact, then build the ramp that lets others enter it.

## Key Quotes
> "Step 1 build the thing. Step 2 build the ramp." - Karpathy's takeaway for technical creators.

> "you might be leaving somewhere 10-100X of the potential" - on inaccessible technical work.

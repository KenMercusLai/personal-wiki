## Summary
Built for Mars analyzes [[HBOMax]] as a streaming app with loved content but weak product execution, comparing it with [[Netflix]] and [[AppleTV]] examples. The case argues that HBO Max's poor ratings are not caused by a wholly broken experience, but by repeated UX judgment errors around image weight, ambiguous availability states, occluded lists, missed conversion journeys, and mobile form behavior. Its reusable lesson is that [[StreamingAppUX]] depends on performance, explicit state, visible controls, and journey design that matches the user's immediate objective.

## Key Claims
- [[HBOMax]] overuses large imagery, creating load-time friction that undermines otherwise attractive visuals.
- Free-versus-paid episode availability should not rely on absence of evidence when the user must make an action decision.
- Partially covered list items create silent frustration because users notice incomplete patterns even when they may not file explicit complaints.
- [[AppleTV]]'s free-episode flow uses timing and default bias to turn viewing into a subscription path, while HBO Max returns the user to the prior state.
- Mobile account-creation forms should keep final fields and CTAs visible, avoid premature inline error states, and use native keyboard affordances.

## Key Quotes
> "Content is great, app is embarrassing" — representative review quoted to separate catalog value from app quality.

> "The key is to maintain visibility on the CTA and the fields." — account-creation form advice.

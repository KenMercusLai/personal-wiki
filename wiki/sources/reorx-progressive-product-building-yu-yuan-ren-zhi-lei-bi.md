## Summary
[[Reorx]] proposes [[ProgressiveProductBuilding]] as a personal correction to repeatedly elaborating product notes while leaving projects unbuilt. The method separates a small idea's stable core from later branches, constrains further planning to implementation details, moves immediately toward a one-day build where feasible, and tracks every simple idea through explicit project metadata. The article frames this workflow change as [[MetacognitiveFeedback]]: notice that an internal rule is producing the wrong behavior, suspend it, and deliberately install a replacement.

## Key Claims
- Excessive up-front product thinking can increase conceptual complexity and expected workload until the creator produces documents rather than products.
- A Simple Project Idea should capture only its purpose and use, then be archived as a stable origin rather than repeatedly expanded.
- A materially evolved idea should become a separate Complex Project Idea linked to its origin, allowing one simple idea to branch without losing provenance.
- The only planned extension to a simple idea should be a technical implementation section that helps an AI coding tool produce the first version.
- Strong contemporary [[VibeCoding]] tools can make some tightly scoped personal projects feasible within a day, supporting an immediate-build default.
- Frontmatter fields such as start date, deadline, completion, and status can expose stalled or abandoned ideas without monitoring every repository.
- Replacing an unproductive product habit requires metacognition that notices the old rule, evaluates its effects, and deliberately adopts a new behavioral rule.

## Key Quotes
> "我最终沦为‘产品文档创作者’而非‘产品创作者’。" - on the gap between elaborating ideas and making products.

> "Simple Project Idea 创建后，应立即着眼于实现。" - on making implementation the next default action.

- [[MetacognitiveFeedback]] - supplies the firmware-upgrade analogy for replacing a counterproductive working rule.
- [[VibeCoding]] - cited as the technical leverage that can make one-day implementation plausible for small projects.
- [[ReleaseFocusedSideProjects]] - shares the priority of reaching a concrete release before scope expands.

## Contradictions
- The article does not directly contradict existing pages, but it qualifies capture-heavy [[IdeaManagement]] by arguing that continued refinement can become a substitute for making.
- The one-day implementation expectation is a personal heuristic enabled by unspecified AI tools, not measured evidence that every simple idea is safe, useful, maintainable, or feasible on that schedule.
